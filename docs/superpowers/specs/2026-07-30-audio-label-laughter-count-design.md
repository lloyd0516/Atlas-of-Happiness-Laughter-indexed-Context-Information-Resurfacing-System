# 回顾音频标签与笑声数量展示修正设计

## 目标

让被试无需理解内部媒体类型或 `Period` 数据结构，也能看懂回顾页面中的音频，并让地图、日历、时间线和回顾列表展示真实一致的笑声片段数量。

## 音频标签

短期与长期回顾页面中的音频行使用以下用户可见标签：

- laughter audio：`笑声音频`
- possible related speech context：`相关上下文音频`

标签只解释音频类型，不改变音频文件、播放增强、波形、进度或研究日志行为。

## 笑声数量口径

为 `EventSummary` 提供统一的用户可见笑声片段数量：

1. 优先统计事件 `auto_captured.audio_clips` 中 `type == "laughter"` 的条目数。
2. 对没有可识别 laughter audio 的旧事件，回退到 `period_ids` 数量。
3. 两者均为零时，用户界面显示 `暂无笑声片段`，不显示误导性的 `0段笑声`。

地图标记、地图下方卡片、日历、时间线和普通回顾卡片均复用这一口径。所有面向被试的 `Period: N` 文案改为 `N段笑声`；内部 JSON 字段和研究日志名称保持不变。

## 兼容性与范围

- 不改变录音、Speechmatics 检测、90 秒聚合、媒体关联、通知选择或日志 schema。
- 旧数据仍可通过 `period_ids` 得到数量。
- 地图同地点聚合时，对各事件的统一笑声数量求和；无有效笑声的事件不凭空按一段计数。

## 验证

- 单元测试覆盖 laughter audio 优先、旧数据回退和真正为空三种情况。
- 展示契约测试覆盖两类音频标签，以及用户可见界面不再拼接 `Period`。
- 运行相关 JVM 测试、完整 JVM 测试并构建 debug APK。
