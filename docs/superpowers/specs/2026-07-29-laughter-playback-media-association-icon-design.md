# 笑声音频增强、媒体时间关联与图标统一设计

## 背景

Atlas 2.0 会被动采集带有 laughter 的 positive moments，并在回顾详情页按笑声 clip
展示音频、照片与视频。当前实现存在三个问题：

1. 录音设备得到的部分笑声非常小，使用手机正常音量播放时难以听清；
2. `EventDetailActivity` 当前忽略 clip 时间，把 event 中所有照片和视频交给每个 clip，
   因而相邻 clip 经常显示完全相同的媒体；
3. 页面内部分笑脸造型不对称，launcher 图标对 laughter 的表达也不够直接。

本设计只调整 App 内的播放体验、clip 媒体呈现和相关图标。它不修改原始音频，不改变
采集、检测、事件聚合、用户补充、删除、地图或 resurfacing 通知逻辑。

## 目标

- 只在 App 播放时提高过小的笑声音量，绝不降低任何 clip 的音量；
- 保留不同 clip 之间可感知的相对强弱，不把所有笑声归一化成同一响度；
- 原始 WAV 永久保持不变，仍可用于后续研究分析；
- 每个笑声 clip 只关联 `±90s` 内最近的 `1` 张照片和 `1` 个视频；
- 没有合格媒体时不补位、不展示空内容；
- 使用统一、自然的“笑声涟漪”图形语言替换相关笑脸和 launcher 图标；
- 对旧 event 数据保持读取兼容，任何新增处理失败时不影响原有播放与浏览能力。

## 非目标

- 不对录制输入或保存的 WAV 做实时增益、降噪、声源分类或永久重写；
- 不判断笑声来自佩戴者还是周围环境；
- 不提供用户可调的增益开关、均衡器或音量设置页面；
- 不改变照片和视频的采集频率；
- 不为窗口外的 clip 人工生成或复制媒体；
- 不重构与本需求无关的页面和后台功能。

## 总体架构

新增三个职责单一的组件：

1. **播放音频准备器**：读取原始 WAV、测量有效响度、计算正增益并生成缓存播放副本；
2. **clip 媒体匹配器**：按媒体时间和 `±90s` 窗口独立选择最近照片、视频；
3. **媒体时间解析器**：读取新结构化时间戳，并为旧数据恢复可信的采集时间。

现有 `EventDetailActivity` 只负责把组件结果绑定到已有播放控件和媒体折叠项，不继续承载
响度算法或匹配算法。

## App 内笑声音频增强

### 数据流

```text
原始 WAV（不修改）
        ↓
后台读取 PCM 与短时帧响度
        ↓
计算只增不减的播放增益
        ↓
生成 App cache 中的增强 WAV
        ↓
现有 MediaPlayer、暂停、波形、进度逻辑
```

### 响度测量

- 处理当前采集链路生成的 PCM 16-bit little-endian WAV；
- 以 `20ms` 音频帧计算 RMS，并使用响度最高 `5%` 帧的平均 RMS 判断笑声主体，避免
  clip 前后 padding 或静音把整体 RMS 过度拉低；
- 同时测量峰值，用于输出保护；
- 不支持、损坏或无法完整解析的 WAV 不做增强，直接回退到原文件。

### 增益策略

初始参数统一定义在 `AppConfig`：

| 参数 | 默认值 | 含义 |
| --- | ---: | --- |
| quiet threshold | `-24 dBFS` | 达到或高于该有效响度时不增强 |
| compensation ratio | `75%` | 只补偿到阈值差值的 75% |
| maximum boost | `+18 dB` | 单个 clip 的最大正增益 |
| output peak guard | 约 `-1 dBFS` | 峰值软保护目标 |
| algorithm version | `1` | 缓存失效与日志解释依据 |

增益始终满足 `gainDb >= 0`。达到正常响度的 clip 使用 `0 dB`；低于阈值时按差值的
75% 增强，并受 `+18 dB` 上限约束。该函数在输入响度上保持单调，因此较大的原始笑声
增强后仍不会变得比原本更小的笑声更弱。它会收窄过大的响度差距，但不会抹平差距。

参考结果：

- `-18 dBFS`：`0 dB`；
- `-32 dBFS`：约 `+6 dB`；
- `-44 dBFS`：约 `+15 dB`；
- 极端更小的信号：最多 `+18 dB`。

当增强后的瞬时峰值超过 `-1 dBFS` 保护点时，对超出部分使用连续的 `tanh` 软饱和，
避免爆音、数字削波以及硬截断产生的尖锐失真。限幅只作用于缓存播放副本，不进入原始
文件。

### 缓存与生命周期

- 增强文件只写入 App cache，不进入研究数据目录，也不随日志导出；
- 缓存键至少包含原路径、原文件修改时间、文件长度和算法版本；
- 原文件或算法变化后必须生成新副本；
- 首次准备在后台线程执行，不阻塞详情页主线程；
- 同一页面只允许最后一个有效播放请求启动；切换 clip、连续点击或退出页面时，过期任务
  不得自行开始播放；
- Activity 销毁后释放播放器、后台任务引用和临时资源；
- 缓存读取、创建或替换失败时播放原 WAV，不能因为增强功能导致“点了没有声音”。

波形仍基于原始 WAV 生成，以保留声音形状的真实表达。现有播放、暂停、动态波形和进度
交互不改变。研究交互日志在播放事件中增加实际 `gain_db` 和 `gain_algorithm_version`，
但不记录音频内容。

## clip 与照片、视频的时间关联

> **媒体关联勘误（2026-07-29）：** 本节原先把“一次 photo + video 采集”误解成
> 每类最多一个媒体。当前规则以
> [`2026-07-29-clip-capture-bundle-correction-design.md`](2026-07-29-clip-capture-bundle-correction-design.md)
> 为准：一次采集固定为 2 张照片 + 1 段视频。

对每个 laughter clip，以其 `device_time_ms` 为中心时间 `T`：

```text
bundle 候选：bundle_time_ms ∈ [T - 90s, T + 90s]
```

- 选择绝对时间差最小的一个采集 bundle；
- 新数据通过共同的 `bundle_id` 分组，bundle 固定最多展示 2 张照片和 1 段视频；
- 旧数据没有 `bundle_id` 时，以视频为优先 anchor，在 15 秒内恢复最多两张照片；
- 距离恰好 `90s` 时包含，超过 `90s` 时排除；
- 时间差相同时选择较早的 bundle；若时间仍相同，使用稳定的 bundle ID 顺序打破平局；
- 同一个 bundle 可以被多个相邻 clip 重复关联；
- 路径为空、文件不存在或当前无法访问的候选不参与选择，并继续检查窗口内下一个候选；
- 时间未知的媒体不参与匹配；
- bundle 中某项采集失败时只展示现有项，不从其他 bundle 补齐；
- 没有合格 bundle 时隐藏整个“照片与视频”折叠项，不保留空白、不显示占位符；
- short-term 与 long-term 详情模式使用同一个匹配器和相同结果；
- 照片查看和视频播放交互保持现状。

### 新数据的媒体时间

未来媒体记录使用明确的 bundle 和媒体时间字段：

- 照片记录实际拍摄触发时间；
- 视频记录实际录制开始时间，而不是保存完成时间；
- 同一轮采集的媒体保存共同的 `bundle_id` 和 `bundle_trigger_time_ms`；
- 两张照片使用 `bundle_media_index` 0、1，视频使用 0；
- 保留当前路径字段和旧数组的读取能力，避免已有代码或旧 event 文件失效。

EventRecord 以只增字段的方式保存结构化媒体元数据，不删除已有 `assets.photos`、
`assets.video` 或 `assets.videos` 兼容字段。

### 旧数据的时间恢复

旧媒体按以下优先级恢复时间：

1. 已有明确的 `capture_time_ms`；
2. 当前稳定路径文件名中的 `event_photo_<毫秒>` 或 `event_video_<毫秒>`；
3. 可信的本地文件修改时间：值大于 `0`，且落在 event 开始前 `90s` 到结束后 `90s`
   的范围内；
4. 仍无法确定时标记为未知。

不得把 event 开始时间当作所有媒体的采集时间。时间恢复与 15 秒 bundle 推断发生在
读取/匹配阶段，不批量重写旧 event 文件。

## “笑声涟漪”图标系统

### 视觉语义

采用已确认的 A 方案：

- 对称、自然的闭合上扬双眼；
- 居中、开怀但不过度夸张的开口笑容；
- launcher 主体下方增加两层扩散弧线；
- 中心笑脸表达 laughter-indexed positive moment；
- 扩散弧线同时表达声音传播和过去回忆再次浮现。

颜色沿用现有暖橙与米白主题，不引入新品牌色。

### 替换范围

- 首页录制状态笑脸；
- 回顾页顶部笑脸；
- 最近记录和地图卡片笑脸；
- 底部笑声/首页导航图标；
- 补充内容选择页面笑声图标；
- launcher 普通与圆形图标；
- resurfacing 通知与前台采集服务的单色通知小图标。

不改变现有布局尺寸、点击区域、文案或导航功能，也不把非笑脸的 event、位置、媒体图标
无关替换。

### Android 兼容

- Android 8.0 及以上使用 adaptive icon，并把主体放在安全区内；
- Android 5.1–7.x 同步更新各密度普通和圆形 launcher PNG；
- 页面图标使用 VectorDrawable；
- 通知小图标使用纯 alpha/白色单色轮廓，满足 Android 状态栏渲染要求；
- `AtlasForegroundService` 不再用彩色 launcher mipmap 作为 small icon，统一改用通知
  专用资源。

## 失败处理

- 音频解析、增益或缓存失败：播放原文件；
- 原文件也无法播放：沿用现有失败提示和日志，不崩溃；
- 媒体时间无效：排除该候选；
- 媒体文件失效：继续寻找窗口内下一个候选；
- 所有候选均无效：隐藏媒体项；
- 图标资源在构建期由 Android resource linking 验证；
- 所有失败均局部降级，不阻断 event 详情页其余内容。

## 测试与验收

### 单元测试

- 正常响度得到 `0 dB`；
- 安静声音按比例增强；
- 增益不为负且不超过 `+18 dB`；
- 输入响度排序在输出目标上保持单调；
- padding 静音不会显著误导有效响度；
- 峰值保护生效；
- PCM WAV 增强副本可解析，原始字节不变；
- 损坏和不支持的 WAV 安全回退；
- `±90s` 两端边界包含，边界外排除；
- 照片、视频分别选择最近的一个；
- 平局选择较早媒体；
- 同一媒体可被多个 clip 复用；
- 时间未知、路径失效和无候选返回空结果；
- 新媒体时间序列化及旧文件名/文件时间恢复。

### 回归与构建

- 运行相关新增单元测试；
- 运行模块完整 debug 单元测试；
- 运行 `:atlasapp:assembleDebug`；
- 确认所有 adaptive、legacy、vector 和通知图标完成资源链接；
- 确认原有采集、事件聚合、补充内容、编辑、删除、照片查看、视频播放、音频进度、
  地图、daily notification 与 location reminder 代码路径未被改变。

### 手工检查清单

- 正常与极小笑声均能播放，正常声音没有被降低；
- 首次增强准备期间页面不冻结，快速切换 clip 不会播放错误音频；
- 播放/暂停图标、真实波形和进度仍同步；
- 每个 clip 只看到窗口内最近的一组 2 张照片 + 1 段视频采集 bundle；
- 无窗口内媒体的 clip 不显示媒体折叠项；
- 首页、回顾、地图、底部导航、launcher 和通知栏图标风格一致且无歪嘴感；
- 卸载/清理 cache 后仍可从原 WAV 正常重新生成播放副本。

## 完成标准

所有新增测试、完整 debug 单元测试和 APK 构建通过；原始音频与旧 event 数据未被重写；
三个需求在新旧数据上按本规范降级或生效，且无原有功能回归。所有实现改动保留在当前
分支；未经用户再次明确授权，不推送到远端。
