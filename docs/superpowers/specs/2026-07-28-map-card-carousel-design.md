# 地图回忆卡片轮播交互设计

日期：2026-07-28

状态：已确认方向，待书面审阅

适用分支：`fj_ver`

## 1. 背景与根因

地图页底部当前使用三张垂直重叠的 `StackedCardView`。真机体验中，卡片难以点击和选择。

现有实现存在以下确定问题：

- 卡片加入 `FrameLayout` 的顺序与“当前卡片”索引相反，视觉上层卡片不一定对应 `topIndex`。
- 触摸只绑定在一个子卡片上，但点击回调固定使用 `topIndex`，可能出现“看到的卡片”和“打开的事件”不一致。
- 后方露出的卡片不能直接选择。
- 切换仅计算纵向位移，虽然代码注释声称支持左右滑动。
- `60dp` 的切换阈值接近卡片高度，操作成本较高。
- `150dp` 容器中存在没有交互响应的空白区域。

## 2. 目标

- 让用户明确知道当前选中了哪一条回忆。
- 让点击结果始终对应当前视觉主卡片。
- 同时支持直接点击、左右滑动和显式按钮切换。
- 保留地图可视面积，不改事件数据、地图聚类或详情页逻辑。
- 对 0、1、2 条以及多条回忆均保持稳定行为。

## 3. 选定交互

地图底部改为紧凑横向轮播：

- 中间显示一张完整的当前卡片。
- 左右边缘露出上一张和下一张的小部分，作为可滑动提示。
- 当前卡片整张区域均可点击，进入该卡片对应的事件详情。
- 左右滑动切换事件，只计算横向位移。
- 有效滑动阈值设为约 `32dp`；低于阈值时回弹，不误切换。
- 卡片下方提供明确的上一张、下一张按钮。
- 中间显示当前位置，例如 `1 / 4`。
- 切换采用循环行为：第一张向前切换到最后一张，最后一张向后切换到第一张。

## 4. 状态与边界

轮播组件只维护：

- 事件总数。
- 当前事件索引。
- 上一张、当前张、下一张的数据索引。
- 当前手势的横向位移。

边界行为：

- 0 条：隐藏轮播和控制栏。
- 1 条：只显示当前卡片；隐藏侧边预览，禁用上一张/下一张按钮，显示 `1 / 1`。
- 2 条：显示当前卡片及一个侧边提示，前后切换均到另一条，避免同一事件同时出现在左右两侧。
- 3 条及以上：显示上一张和下一张的左右侧边预览。
- 页面重新加载事件后回到第一条，即最新的有定位事件，保持现有排序规则。

## 5. 组件边界

新增一个纯 Java 状态模型，负责索引计算和循环切换，不依赖 Android View：

- 设置事件总数。
- 获取当前、上一张和下一张索引。
- 向前或向后移动。
- 生成从后景到前景的绘制顺序，确保当前卡片最后绘制并位于最上层。

`StackedCardView` 负责：

- 根据状态模型创建当前卡片和侧边预览。
- 绘制和动画。
- 识别横向点击/滑动。
- 把当前事件索引传给点击回调。
- 向页面报告当前位置变化。

`ReviewShellActivity` 负责：

- 继续提供按时间倒序排列的有定位事件。
- 处理上一张/下一张按钮。
- 更新 `当前位置 / 总数`。
- 使用收到的准确事件索引打开 `EventDetailActivity`。

## 6. 不在本次范围内

- 不修改地图地点聚类规则。
- 不修改同地点通知的 50 米策略。
- 不修改地图标记样式或标记点击。
- 不修改事件详情页、日历页和时间线页。
- 不改变事件排序、筛选或数据结构。
- 不新增第三方轮播库。

## 7. 测试与验收

自动测试覆盖纯状态模型：

- 当前索引与视觉主卡片索引一致。
- 下一张和上一张正确循环。
- 1 条事件不会产生无效侧边索引。
- 2 条事件不会把同一条同时作为左右预览。
- 绘制顺序最后一项始终是当前卡片。

构建验证：

- 完整 JVM 单元测试通过。
- Debug APK 构建通过。
- `git diff --check` 通过。

真机验收：

- 当前卡片整张可点击，且打开的事件与卡片标题、时间一致。
- 左右滑动约 `32dp` 即可切换，纵向小幅移动不会误切换。
- 上一张/下一张按钮能够稳定切换。
- 当前位置文本随切换更新。
- 侧边预览只作为提示，不遮挡当前卡片内容。
- 地图仍可拖动、缩放，轮播区域以外的地图手势不受影响。
